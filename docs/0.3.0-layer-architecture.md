# GDDraw 0.3.0 Layer Architecture

This document is the durable implementation and handoff plan for the 0.3.0
layer release. Read it with `docs/architecture.md`, then inspect the current
worktree before continuing. Repository state and passing tests are authoritative;
do not repeat completed work only because the implementing agent changed.

The authoritative live checkpoint is now
[`0.3.0-current-handoff.md`](0.3.0-current-handoff.md). The older “Current
Handoff” section near the end of this document is retained only as an historical
mid-implementation checkpoint and must not be used to restart completed work.

## Product Contract

Layers are shared document state, not a feature owned by either viewport. The
Layers panel therefore remains at the far right in 2D, 3D, and both split
layouts. Collapsing it leaves a narrow toggle rail; expanding it reveals a
resizable panel without changing the selected view mode.

The user-facing tree contains three deliberately different concepts:

1. **Object groups** mirror imported scene/object hierarchy. They organize
   ownership and preview selection but are not raster compositing layers.
2. **Paint targets** identify compatible raster destinations. A target binds an
   object and mesh surface/material channel to one image size, UV set, texture
   path, and save destination.
3. **Layer nodes** are paint layers or nested layer groups inside one target.
   Only these nodes participate in raster compositing.

Textures with different channels, sizes, UV sets, or save destinations must not
be placed in one layer stack. They are separate paint targets even when they
belong to the same object group.

## Ordering And Compositing

Layer-node arrays are stored in UI order: index `0` is visually topmost.
Compositing walks them in reverse order using straight-alpha source-over.

- Hidden nodes contribute nothing.
- Paint-layer opacity modulates that layer before source-over.
- A group is first composited into a temporary transparent image. Group opacity
  is applied once to that result, preserving normal group semantics.
- Locking affects editing, movement, deletion, and routing; it never changes the
  rendered result.
- Every target always contains at least one paint layer and always identifies a
  selected paint layer. Groups and object rows cannot become brush destinations.

The imported PNG or 3D texture becomes the initial selected **Base** paint
layer. Each paint layer retains its own eraser-source snapshot. This preserves
the current behavior where erasing edits to an imported texture restores its
original pixels, while erasing a newly created transparent layer restores
transparency.

## Session State

A layer session owns object groups, paint targets, the active target ID, and the
target-lock state. Each paint target independently remembers its selected layer.
Changing the active target therefore restores that target's prior selection.

A 2D document is represented by one document object group and one RGBA paint
target. A 3D session may contain many object groups and paint targets. This
shared representation replaces the current architectural assumption that a 3D
session temporarily turns the one 2D canvas image into the active texture.

The canvas remains a raster editor. During migration it edits only the active
paint layer while the session owns the authoritative tree and composite. The
canvas must eventually receive a separate composite display image so drawing
math can continue operating on the selected layer without hiding lower layers.
Eyedropper behavior should sample the displayed composite; fill and selection
mutations remain scoped to the selected paint layer.

## 3D Discovery And Routing

Import scope must support:

- the selected editable surface only;
- editable descendants in the selected object hierarchy; or
- all explicitly selected objects and their editable descendants.

Discovery is read-only until the user confirms creation of a missing material or
texture. One object group is created for each retained scene object, preserving
useful parent/child relationships. Each supported surface/material channel
becomes its own paint target.

A paint hit resolves this complete key before changing pixels:

`preview instance -> source object -> mesh surface -> material channel -> UV -> paint target -> selected paint layer`

If target lock is enabled, hits on any other target are ignored. If it is
disabled, a valid hit activates the resolved target, restores that target's
selected layer, synchronizes the Layers panel and 2D canvas, and then paints.
A drag may not interpolate across target boundaries.

## History, Dirty State, And Persistence

History entries must snapshot the layer-session mutation needed to reverse an
operation, not only a flattened image. Pixel strokes, layer operations, target
selection changes that affect editing, and structural changes need coherent
undo/redo behavior. View-only panel expansion, scroll, and preview selection do
not make the document dirty.

Dirty state compares the complete persistable session against its saved
baseline. A successful PNG texture save advances only the affected target's
flattened-output baseline. A layered-project save advances the complete session
baseline. Exporting/saving a PNG always writes the target composite, never only
the selected paint layer and never silently destroys the in-memory stack.

Layered persistence needs a versioned format with stable IDs, hierarchy,
properties, target bindings, and lossless RGBA layer images. Format choice and
migration must be settled before declaring 0.3.0 persistence complete; a flat
PNG alone is not evidence that layers persist.

A 3D layered document keeps geometry external. It records the edited source
scene's project path and resource UID plus each bound object's path relative to
that scene root. Opening from another scene is an explicit dependency workflow:
open the recorded scene, relink compatible relative paths in the current scene,
or open only the embedded layers. Missing source scenes are detected before any
workspace replacement, reported visibly, and cannot be opened through a stale
action. Legacy documents without scene identity retain their active-scene,
absolute-path behavior.

## Phased Implementation

1. Add and test independent layer-node, paint-target, session, compositing, and
   snapshot primitives.
2. Adapt history and the canvas so the selected layer is editable while the
   merged composite is displayed and saved. Establish the one-target 2D path.
3. Add the far-right collapsible/resizable panel and standard layer operations.
4. Convert one-surface 3D sessions to paint targets without regressing current
   save, eraser, UV, preview, scene-detachment, or transform behavior.
5. Add hierarchy/multi-selection discovery, multiple preview instances, target
   routing, per-target selection memory, and target lock.
6. Add versioned persistence, migration/backward compatibility, performance
   work, complete tests, documentation, and release polish.

Phases 1-3 and the one-target portion of phase 4 are implemented:

- `gddraw_layer_node.gd` adds recursive paint/group nodes and defensive deep
  snapshots.
- `gddraw_paint_target.gd` adds layer invariants, ordering, nested-group
  compositing, visibility/opacity/lock state, movement/deletion safety,
  selected-layer replacement, per-layer eraser sources, binding metadata, and
  document-space layer origins. Paint images may retain bounds larger than the
  target. Canvas resize changes the export/UV frame without clipping retained
  pixels, crop moves that frame relative to every layer, and Scale Image
  transforms layer pixels, eraser sources, and origins together.
- `gddraw_layer_session.gd` separates object groups from paint targets, retains
  each target's layer selection, routes hits with optional target lock, and
  snapshots the complete in-memory session.
- `gddraw_3d_layer_discovery.gd` performs read-only discovery for selected-
  surface, selected-hierarchy, and explicit multi-selection scopes. It retains
  useful object paths, deduplicates overlapping selections, reports unsupported
  material slots, and emits stable source/slot/channel/UV binding keys.
- `gddraw_3d_layer_coordinator.gd` converts a confirmed discovery result into
  one shared layer session while retaining one existing, battle-tested
  `GDDraw3DTextureSessionResource` per paint target. It synchronizes explicit
  activation and binding-key routing, honors Target Lock, aggregates dirty
  state, and batches the confirmation requirement for missing targets. It is
  model-tested but is not connected to the dock picker yet.
- `gddraw_history.gd` accepts legacy image entries and tagged, deeply copied
  layer-session entries. Pixel, property, structural, opacity-drag, locking,
  reorder, grouping, deletion, and target-wide transform changes now undo and
  redo without flattening the stack.
- `gddraw_canvas.gd` now keeps editable pixels separate from an optional merged
  display image. The merged boundary covers ordinary display, tile preview,
  eyedropper sampling, 2D shape previews, and 3D surface-shape previews without
  changing existing raster algorithms. Its backing workspace is the union of
  the selected layer and fixed document frame; selection commits can expand it,
  while UV input and final output remain mapped to the document frame. View
  fitting, zoom anchoring, and bounded middle-mouse/Pan-tool movement also use
  the document frame, so layer-bound changes cannot shift the canvas. Its
  editing gate blocks all mutation paths when the selected layer or an ancestor
  is locked.
- `gddraw_dock.gd` initializes a one-target layer session for 2D and current
  one-surface 3D work, synchronizes canvas edits into the selected layer,
  preserves the 2D layer session around 3D work, and uses the composite for PNG
  save, dirty checks, sprite/CSG creation, 3D preview, Save, and Save As. It now
  owns a far-right outer split whose collapsed Layers icon rail remains stable
  in 2D, 3D, horizontal split, and vertical split. The expanded resizable panel
  exposes object/target/layer rows, thumbnails, selection, rename, visibility,
  opacity, lock, add, group, reorder, delete, and target lock.
- `tests/test_layer_model.gd` covers model and dock/canvas bridge behavior with
  598 assertions. Its refinement coverage includes the selected inspector,
  fixed row actions, selection-only clicks, effective locks, deterministic
  reparenting, recursive/locked drop rejection, delete cancellation, independent
  and shared-atlas Target Lock routing, scene-binding synchronization,
  transactional save reuse, and protected New File history isolation. This
  development test lives under the repository's ignored `/tests/` path like the

- Panel action icons live in their Lucide-named directories under
  `addons/GDDraw/icons/`. Inactive, active/hover, and disabled variants follow
  the existing GDDraw icon-color convention.

The panel hierarchy is model-backed. Move Out reparents an item to its current
group's parent immediately after the group. Move Into prefers the neighboring
group above and appends to it, otherwise uses the neighboring group below and
inserts at its top. Drag-and-drop translates Tree before/on/after drop sections
into the same parent/index contract. Model validation rejects self/descendant
destinations, no-op drops, locked sources or descendants, and locked destination
groups before a history entry is created.

The selected hierarchy item and editable paint destination are separate states.
The Tree selection background identifies the former; the persistent blue name
accent identifies the latter even when a group is selected. Group inspectors
use a folder icon rather than compositing the group, avoiding a full-stack image
generation cost on selection and during live refresh. Paint inspectors generate
bounded thumbnails only during panel refresh, while the 4096-square live canvas
continues using the direct selected-layer display path.
