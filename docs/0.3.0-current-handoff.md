## Implemented Product Behavior

The Layers panel is shared state at the far right of 2D, 3D, horizontal split,
and vertical split layouts. It starts as a narrow inactive rail and opens into
a resizable panel. It exposes object groups, paint targets, nested layer groups,
paint-layer thumbnails, selection, rename, visibility, opacity, lock, add,
group, reorder, delete, and Target Lock. Every target retains at least one
selected paint layer.

The model is split deliberately across:

- `gddraw_layer_node.gd` for recursive paint/group nodes;
- `gddraw_paint_target.gd` for per-raster stacks, compositing, eraser sources,
  invariants, and whole-stack transforms;
- `gddraw_layer_session.gd` for object hierarchy, targets, active routing,
  complete-session dirty baselines, and snapshots;
- `gddraw_history.gd` for deep session undo/redo alongside legacy images; and
- `gddraw_canvas.gd` for separate editable-layer and displayed-composite state.

Scoped 3D import supports one selected surface, a selected object hierarchy, or
all explicitly selected objects. Discovery is read-only. Missing materials and
textures require one explicit confirmation before mutation. The coordinator
retains one proven primary texture session per paint target and presents a
shared layer session to the dock. When multiple scene bindings use the same
path-backed PNG, they share one paint target/layer stack while retaining
separate preview, transform, geometry, UV, and hit-routing sessions. The shared
target is referenced by every owning object group and persists every stable
scene binding.

The 3D preview renders the active target plus every imported context target at
its authored transform. It frames their combined bounds, refreshes live linked
transforms and geometry for active and context targets, and supports separate
material slots on one mesh without duplicated full-mesh rendering or
z-fighting. Each preview instance renders only its owned surface slots. Camera
framing may follow the combined bounds, but the stage grid and colored axes stay
anchored at the authored scene origin; asymmetrical meshes and multi-object
bounds must never relocate that coordinate reference.

Ray hits resolve the owning target across all preview instances. Target Lock
rejects neighboring targets; unlocked stroke starts activate and synchronize
the target, canvas layer, eraser source, UV overlay, status, and preview. A drag
cannot interpolate across target boundaries. Multi-target dirty handling walks
each dirty flattened texture deliberately before allowing a replacement or
exit. Structural-only layer changes also trigger layered preservation even when
the flattened pixels are unchanged.

Independent scene bindings that resolve to the same existing PNG are merged
into one shared paint target. This removes competing layer stacks and duplicate
save destinations while allowing all authored objects/surfaces using the atlas
to remain visible and paintable. Different PNG destinations remain independent
targets.

## Layered Persistence

`gddraw_layer_document.gd` implements the versioned `.gddraw` format. It is a
ZIP archive containing `manifest.json` plus lossless PNG payloads for every
paint layer, eraser source, and saved target composite. The manifest preserves
stable IDs, hierarchy, properties, target bindings, active selections, target
lock, allocation serials, source-scene path/UID, and scene-relative object
paths. Meshes and other 3D scene resources remain external dependencies rather
than being duplicated into the archive.

Save uses a temporary ZIP and replacement transaction. Load enforces manifest,
entry, count, byte-size, image-dimension, path, schema, image, and model
validation into a temporary session before replacing open work. Unsupported or
malformed documents cannot partially mutate the current session. Opening a
saved 3D project resolves its stable scene-node bindings and prepares every
texture session before activation; missing/renamed/incompatible scene targets
leave the current work unchanged.

When a 3D layered project is opened from a different scene, GDDraw preflights
the recorded source scene before replacing the workspace. The dependency dialog
can open that scene and continue, relink the saved relative object paths against
the current scene, open the embedded layers without a 3D preview, or cancel. If
the recorded scene cannot be found, its path remains visible, a red follow-up
states that the original scene is unavailable, and Open Source Scene and
Continue is disabled. Layers-only documents retain their scene dependency and
offer Relink Current Scene from the empty 3D view. Documents created before
this metadata was added continue to resolve their legacy absolute bindings in
the active scene.

File Open accepts images and `.gddraw` projects. File > Save Layered Project
preserves the full stack. Ctrl+S updates an already-open 2D layered project,
while PNG Save/Save As remains a flattened export. Starting/replacing sessions
routes structured unsaved work to the layered workflow. Flat PNGs remain the
backward-compatible migration path and initialize one Base layer.

The stable updater's required-file contract includes every new layer,
discovery, coordinator, and persistence script.

## Layer Refinement Findings and Fixes

The August 2026 refinement pass confirmed and fixed these separate ownership
problems:

- The expanded Layers controls were built directly on the dock surface, and the
  hierarchy mixed flexible labels with action content. The expanded content now
  uses the existing 2D canvas-area surface color, while the rail stays on the
  editor background. The hierarchy has one clipped, expanding name column and
  four fixed 26-pixel action columns for Rename, Visibility, Lock, and Delete.
  A selected-item inspector above the hierarchy owns the larger preview, name,
  type, and opacity. Paint thumbnails frame nontransparent bounds with padding;
  Base and filled layers use the full canvas, and empty layers show the
  checkerboard. Groups deliberately use the folder representation instead of a
  full-stack composite so selecting a group cannot introduce full-resolution
  work into the live drawing path.
- A Tree row was editable on selection, which conflated selecting with naming.
  Rows are read-only until their Rename button starts the Tree's native inline
  editor. A follow-up native crash showed that selecting a non-selected row from
  its compact button synchronously rebuilt the Tree, then continued the button
  callback with an invalid `TreeItem`. Compact row actions now retain only
  stable target/node IDs and defer selection, lookup, editing, and mutation until
  Godot finishes dispatching the native click. Row Delete stages a stable-ID
  context and mutates only after confirmation. Cancel clears only that context.
  The model rejects removal of the final paint layer and rejects rename,
  opacity, delete, reorder, or structural changes through an effective ancestor
  lock; visibility remains independent. Child direct-lock flags are not
  flattened when a parent is locked.
- Reparent rules previously lived only in relative UI movement. The paint-target
  model now validates arbitrary destinations, recursive drops, locked subtrees,
  locked destination groups, Move Out, and deterministic Move Into. Tree
  drag-and-drop and toolbar callbacks capture one deep undo snapshot, call those
  model operations, and retain stable IDs, target selection, and dirty state.
- Target Lock itself was retained by the layer session and hit routing already
  consulted it, but editor scene selection was ignored whenever a coordinated
  3D session was active. This let the scene selection, preview binding, panel
  row, and active paint target disagree. The coordinator now resolves source
  nodes to binding identities. Accepted unlocked selection/hits synchronize the
  binding, target, canvas, UV/session data, panel row, and Godot scene selection;
  locked cross-target selection/hits leave all of them unchanged. Shared-PNG
  objects still track distinct binding keys while sharing one paint target.
- The previously reported layered-save dialog lockout was not reproducible on
  the current build: first save, replacement, cancel, validation failure, and
  archive commit failure all remain reusable. The archive transaction did have
  two recovery gaps: a failed packer open could retain its temporary name, and
  a failed destination replacement did not report a failed backup restoration.
  Temporary cleanup and recovery-path reporting now cover those branches. The
  session path/baseline advances only after commit, and tests verify no normal
  `.writing-*` or `.replacing-*` remnants.
- New File directly resized the current canvas, pushed the old document into
  undo, cleared only redo, had no dirty guard, and was disabled during 3D
  editing. It is now a first-class protected session transition. Dirty pixels,
  layer structure/properties, text drafts, and 3D targets use Save, Continue
  Without Saving, or Cancel. Completing New creates a clean Base document,
  clears both history stacks and every old path/saved-workspace field, and does
  not permit Undo to cross the document boundary.

## Verification At This Checkpoint

Oversized layer support now uses one uniform paint-layer model. Every paint
node stores an RGBA image plus a document-space origin; there is no user-facing
special layer type. The canvas keeps a fixed document/export rectangle inside
an expandable selected-layer workspace and draws that rectangle as the canvas
boundary. Imported oversized images enter the existing floating selection
workflow, commit without clipping, remain selectable across their full bounds,
and are cropped only while composing the target-sized PNG or 3D UV texture.
Canvas resize preserves layer pixels, crop moves the frame, and Scale Image
rescales both pixels and origins. The version-2 `.gddraw` archive records native
layer dimensions and origins while continuing to load version-1 archives.
The 2D view transform is anchored to that fixed document frame rather than the
selected layer workspace, so changing between differently sized layers cannot
move the canvas on screen. Middle-mouse drag and the Pan tool can reposition a
zoomed-out canvas anywhere inside the drawing panel; its edges remain clamped
to the panel's existing eight-pixel margin.
Accepting an oversized floating import now uses `Image.blend_rect()` with an
explicit clipped source rectangle instead of a per-pixel GDScript loop. The
4096-square-on-128-square headless commit benchmark completes in about 180 ms
on the development machine, removing the multi-second first-switch stall.
